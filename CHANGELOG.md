# Changelog

## 0.2.2 — 2026-09-07

### Added

- Author credit in the report footer ([hernan.tech](https://hernan.tech))

### Fixed

- The HTML self-containment property test was missing an `await` and had
  never executed its assertions; once armed it caught a static
  `href="https://…"` literal in the personal-mode share button, now built
  dynamically like the main share bar. Generated reports verify clean of
  static external `src`/`href` references

## 0.2.1 — 2026-09-07

Display fixes found while testing 0.2.0 against real-world repositories.

### Fixed

- Terminal report now respects its 20-hotspot limit instead of printing a
  table row for every changed file in history (a run against expressjs/express
  printed 900+ rows), with a "... and N more files" footer
- The summary stat previously labeled "Code Hotspots" showed the HTML
  truncation cap (100) instead of a real number; it is now "Changed Files"
  and reports the true pre-truncation count (new `totalFileCount` field in
  the JSON export)
- Knowledge-silo risk groups are now keyed by the file's parent directory —
  a two-segment path like `benchmarks/README.md` no longer renders as a
  directory containing itself; top-level files group under `./`

## 0.2.0 — 2026-09-06

Security release. HTML reports generated by earlier versions could execute
attacker-controlled scripts when opened (content from git history — file
paths, author names, branch names — was not escaped). Regenerate any reports
you have shared.

### Security

- Fixed stored XSS in generated HTML reports: git-controlled strings are now
  escaped both in the embedded JSON payload (`</script>` breakout) and at
  every DOM insertion point in the report template
- Fixed shell injection through the `--output` path when auto-opening the
  report in a browser (array-form spawn, no shell)
- Fixed git argument injection through `--branch` values starting with `-`
- Upgraded the bundled ECharts 6.0.0 → 6.1.0
  ([GHSA-fgmj-fm8m-jvvx](https://github.com/advisories/GHSA-fgmj-fm8m-jvvx))

### Fixed

- ECharts inlining no longer corrupts `$$` sequences via `String.replace`
  `$`-patterns — earlier versions shipped a subtly modified ECharts bundle in
  every report
- Reports now generate correctly under pnpm and hoisted `node_modules`
  layouts (ECharts resolved via module resolution, not a hardcoded path)
- Non-ASCII file paths are no longer octal-escaped (`core.quotePath`) or
  corrupted at stream chunk boundaries (UTF-8 decoding at the source)
- Renames are attributed to the new path in hotspot analysis instead of a
  tab-joined `old\tnew` composite
- Failed remote clones and Ctrl+C no longer leak temp directories
- `--json` can no longer overwrite the HTML report when the output path lacks
  an `.html` suffix; missing output directories are created automatically
- Exit code 1 when analysis produces no data (unknown branch, repo without
  commits) instead of writing an empty report and exiting 0
- Git failures during analysis degrade gracefully instead of crashing with an
  unhandled stream error
- Worktrees and submodules now validate as git repositories; a stray `HEAD`
  file no longer false-positives as a bare repo
- Progress output no longer emits terminal control sequences into CI logs

### Changed

- Stricter argument parsing: unknown single-dash flags, missing flag values
  (`--author --json`), and extra positional arguments are now errors instead
  of silent misparses (`--flag=value` remains available for values that
  legitimately start with `-`)
- git processes killed by signals are treated as failures instead of
  producing silently truncated results

### Internal

- CI: Linux/macOS/Windows × Node 20/22/24 matrix running typecheck, lint,
  coverage-gated tests, and build; packaged-CLI smoke test on Node 18
- End-to-end regression suite against real git repositories (XSS payloads,
  unicode paths, renames, merges)
- Tests are now typechecked; ESLint added; coverage thresholds enforced;
  `prepublishOnly` gated on all of the above
